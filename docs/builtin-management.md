# 内置广告库管理

入口：WebUI **规则管理 → 内置广告库**（`#/builtin`）。

内置库 **2.3.0** 提供 22 项离线组合检测，按类别展示条件、版本和命中原因，
支持总开关、逐项启停及文本测试。检测逻辑随程序发布；需要新增或编辑
自己的正则时使用「自定义规则」。检测、设置目录和中文名称来自同一注册表。

## 判定与能力边界

- 洗钱、洗资、催情迷情药物等高风险主题必须结合交易、招募或主动联系招揽；没有链接的广告也能命中。
- 跑分、代收代付、USDT、四件套等歧义词需要同类独立风险证据。普通术语或价格单位不是广告结论。
- 行业黑话按“两个独立信号”判定：马车、车队、水房、四件套、老群、拍照、会所、上门等词单独出现时都有正常含义，必须同段再出现另一类独立信号（结算或保障承诺、招募或供给动词、色情或价格标记、买卖术语）并带联系入口。汇率只在紧邻数字或“高/美丽”等修饰时算作跑分结算证据，避免与正常换汇讨论混淆。
- 维修、安装、保洁、搬家、家政、摄影等普通上门服务即使带技师、价格和联系电话也不判定为招嫖暗语。
- 广告代发、群发、站群、引流等服务需要同时出现投放对象与支付结算、套餐报价或 VCC 虚拟卡；只讲投放技巧或流程公告不判定。
- 日入、日赚、一天赚加金额，或日结加金额属于收益承诺，可作为商业招揽证据；但“工地项目招人，日结300”这类普通用工需再出现挂机、短剧、拉代理等项目词才判定。
- 水货、水果机、港版美版、卡贴机、华强北等货源词与数码商品、只要特价现货拿货等推销词组合才判定；机型讨论、二手机转让和门店进货通知不判定。
- 邀请链接、短链、机器人提及和频道转发也需要商业推广或交易证据；普通邀请、新闻分享及机器人帮助不再因这些元数据本身而删除。
- 检测先提取原始实体，再对副本做 NFKC、大小写、精选繁体与别名、零宽字符处理。受控高风险词支持有限的字间装饰符，不把不同段落拼成词组。
- 独立、精确的洗钱或药品高风险短标题可给紧邻下一段提供主题证据，覆盖标题与接单说明间的空行；普通叙述、弱词标题和不相邻段落不继承。每个按钮独立分析，明确购买或自我招揽按钮才与正文结合，多个功能菜单不会拼成一笔交易。
- 报道、引用和否定按局部语境处理；“反诈”“科普”等字样不会让其他段落中的真实接单广告免检。
- 处理 Telegram 实际投递的正文、媒体说明、新消息及编辑、隐藏链接、普通联系人和内联按钮；转发来源只作辅助。URL 仅在本地解析，不联网访问或展开短链。
- 不识别图片像素、二维码、OCR、语音、文件名，不合并多条消息。Bot API 未投递的内容无法检查。可选的简介辅助检测见下节。
- 自定义正则继续匹配原文。内置库优先命中后只执行一次删除和审计；未命中才执行自定义规则。

## 简介辅助检测（可选）

默认关闭，可在面板「设置 → 运行设置」或由机器人所有者发送 `/settings bio_check on|off` 随时开关，
保存后立即生效、无需重启；`.env` 的 `BIO_CHECK_ENABLED` 只作为尚未保存过配置时的初始值。
正文检测及自定义规则都未命中时，正文或媒体说明中的“看我主页”“查看本人的资料”
“点我头像”等主动引流表达才触发 `getChat(user_id)`。简介作为独立文本进入当前
内置库；不与消息拼接，也不送入自定义正则。两项条件同时成立才删除消息并计次。
内置库总开关和逐项开关同样适用于简介，面板保存后立即用于缓存简介的下次判断；
内置库总开关关闭时不会发起任何简介查询。

引用、代码、否定、反诈提醒及转发内容不作为本人主动引流；匿名管理员、频道身份、
机器人及缺失有效用户 ID 的消息不查询简介。简介内普通个人网址或频道链接不单独判广告。
入群审批和个人账号登录不在此功能范围内。

Bot API 不保证返回每位成员的简介。查询超时 2 秒，全局每秒最多启动 1 次；配额
不足、访问失败或无简介时跳过本次辅助判断，`429` 按 `retry_after` 暂停新查询。
缓存最多 10,000 项，按用户共享并按 LRU 淘汰；成功结果含空简介缓存 10 分钟，
失败缓存 1 分钟；相同用户的并发查询合并。不会持久化完整简介。

简介命中沿用原检测项 ID、名称与版本，审计追加“消息主动引流”和
“证据来源：用户简介”标签，面板审计详情和 `/adlog` 可查看。正文摘要、删除通知、
同消息去重计次和管理员累计封禁保护沿用现有流程，无新增数据库迁移。

## 配置与生效

- 新安装且没有保存配置时，总开关取自 `ADFILTER_ENABLED`，所有单项默认开启。
- 面板保存后，`builtin_settings` 表中的配置优先于环境变量。
- 保存成功后立即用于后续检测；已经开始处理的消息可能仍使用原配置快照。
- 保存失败时运行中的配置保持不变。并发修改不同检测项会合并，修改同一项以最后成功的请求为准。
- 重启后会恢复数据库配置，包括 WebUI 被关闭的情况。
- 关闭总开关会暂停所有内置检测，但保留单项选择；自定义规则不受影响。
- 单项关闭仅移除该项判断，同一消息仍可能命中其他内置项或自定义规则。
- 程序升级新增的检测项默认开启，已有检测项的停用状态按稳定 ID 保留。

数据库设置继续使用 `0006_builtin_settings.sql`。新增迁移
`0007_builtin_details.sql` 为审计增加可空的 `builtin_details` JSONB 和计次索引；
保留旧 `builtin_hits`、原文哈希及 120 字摘要。迁移随程序启动自动执行。

升级后旧六项 ID 和停用选择保留，但裸链接必删语义调整为组合判断。
新分类默认开启。已有审计不会被新版检测器重新分析来生成历史原因。
同群同用户在时间窗口内按不同 `message_id` 计封禁次数，编辑和重复投递的
多条审计只贡献一次；默认仍是 3 条不同消息 / 24 小时。

## API

接口使用现有 WebUI 登录会话 Cookie。PATCH 和 POST 请求还需
`Content-Type: application/json` 和 `X-Requested-With: fetch`。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/builtin-rules` | 获取总开关、检测目录、单项选择及实际生效状态 |
| PATCH | `/api/builtin-rules` | 部分更新总开关或指定检测项 |
| POST | `/api/builtin-rules/test` | 按当前配置测试一段文本，无删除、审计或计次副作用 |

GET 和成功的 PATCH 返回：

~~~json
{
  "enabled": true,
  "library_version": "2.3.0",
  "rules": [
    {
      "id": "ad_bot_mention",
      "name": "机器人引流广告",
      "category": "通用导流",
      "description": "机器人提及或机器人链接，并在邻近内容中出现明确商业推广或交易招揽；普通分享不命中。",
      "conditions": ["机器人提及或机器人链接", "邻近内容有商业推广或交易招揽", "排除局部否定、报道与引用语境"],
      "enabled": true,
      "effective": true
    }
  ]
}
~~~

示例只展示一个检测项，实际返回全部目录，客户端应使用实际数组长度。
`conditions` 是组合条件说明；旧的可选 `pattern` 字段保留兼容，不代表完整判定。
`enabled` 是单项选择，`effective` 表示总开关与单项开关同时开启。

关闭总开关：

~~~json
{"enabled": false}
~~~

开启总开关并停用机器人提及检测，其他检测项保持原配置：

~~~json
{"enabled": true, "rules": {"ad_bot_mention": false}}
~~~

### 文本测试

使用相同登录 Cookie、JSON 请求头和 `X-Requested-With: fetch` 提交：

~~~json
{"text":"承接洗资业务，联系 @example_agent"}
~~~

返回与实际检测相同的分析结构：

~~~json
{
  "enabled": true,
  "matched": true,
  "library_version": "2.3.0",
  "hits": [{
    "id": "ad_money_laundering",
    "name": "洗钱与洗资招揽",
    "category": "资金洗白",
    "evidence": ["洗钱洗资主题", "交易或联系招揽", "联系入口"]
  }]
}
~~~

最多接受 4096 个 Unicode 字符；缺失、null、空白、超长文本或未知字段返回 400。
总开关关闭时 `enabled=false`、`matched=false`、`hits=[]`；单项开关同样生效。
样本文本不写审计、不触发 Telegram 请求。此入口仅测试文本，不能模拟未提供的
隐藏链接实体、转发或按钮；这些场景在自动化消息样例中验证。也不会查询或组合用户
简介；可以单独粘贴简介测试其是否满足广告条件，但这不代表群消息已满足主动引流条件。

### 审计解释

新审计的 `builtin_details` 包含 `library_version` 和 `hits`，命中结构与上述相同。
其中只保存目录元数据和简短证据标签，不保存额外的原文片段或完整 URL。
旧记录缺少该字段时仍展示 `builtin_hits`；未知历史 ID 原样显示。
`/adlog` 也显示内置命中与已有解释。文本测试结果表示提交时的配置快照。

## 验证

单元及竞态测试覆盖分类正反例、混淆变体、上下文、实体和按钮、命令前缀、
逐项停用、总开关、存储失败、配置重载及并发更新。浏览器回归覆盖分类和版本、
文本测试、历史审计解释、安全文本展示、开关失败回滚及手机布局。

真实数据库往返测试需要单独提供 `TEST_DATABASE_URL`：

~~~text
go test -race ./internal/store -run '^(TestBuiltinSettingsRepositoryIntegration|TestPanelAuditBuiltinHitsIntegration|TestAuditDistinctMessagesIntegration)$' -count=1 -v
~~~

这些用例分别创建和清理自己的临时 schema，并自动应用迁移；覆盖新旧审计、
JSONB 往返、原文摘要/哈希、窗口边界及重复消息计次。没有该变量时会跳过。
详见 [WebUI 开发验证](webui-development.md)。

## 发布与回滚

库内容变更时同步提升 `LibraryVersion`、补充独立正反例及规避变体，再发布固定程序版本。
在测试群验证删除权限、话题通知及计次后部署；上线后抽查命中与删除失败审计。
发现某检测项误判可即时停用该 ID。需要整版回滚时恢复上一个固定镜像，新增可空
审计列不会影响旧程序读取，保留数据库备份即可。
